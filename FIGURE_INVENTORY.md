# Figure Inventory & Consolidation Plan

**Purpose.** Catalog every figure the analysis stack can produce, across all three
current pathways, so we can decide the *canonical* figure set and where it is
produced. **Design direction (Alex, 2026-07-08):** make **source-analytics the
single figure producer** — figures live next to the results, usable without the
gallery — and **slim source-lightbox** down to a consumer that embeds
analytics-produced images (and/or *calls* analytics' figure generation), rather
than carrying its own bespoke renderers.

Evidence is cited as `file:line`. SA = source-analytics
(`~/sandbox/source-analytics`); LB = source-lightbox (`~/sandbox/source-lightbox`).

**Cost note for a figures-only pass:** `roi_psd/roi_aperiodic/roi_directed` regenerate cheaply from cached data (R `--figures-only`). The Python vertex modules regenerate only if their `figures()` state (`_source_coords`, cluster results) is reloaded by `setup`. **`electrode_psd/aperiodic` are the exception** — their figures are written *inline during `statistics()`* (with `--no-figures` when figures aren't in steps), so they need a `statistics` re-run with figures enabled, not a cheap figures-only pass.

**`--no-figures` gotcha:** the R scripts stub `ggsave <- function(...) invisible(NULL)` but still `message("  Saved: X.png")` (plot_psd.R etc.), so logs claim saves that never hit disk. Don't trust the log; trust `results/figures/`.

## 6. Recommended target architecture (for the slim-down)

**Principle:** every canonical figure is produced by **source-analytics** and written to `results/figures/…`, so it exists with the results regardless of the gallery. Lightbox becomes a **scanner + gallery builder** that embeds those PNGs, with an *optional* thin hook to trigger SA figure generation when a figure is missing.

**Target division of labor**
- **SA owns all figure code.** Pathway A (module `figures()`) is the canonical set; Pathway B (`figure` CLI) is the on-demand/study-agnostic summary set. Both already write to `results/figures/`.
- **LB keeps only:** `scanner.py` (reuse PNGs), the gallery/manifest/HTML builder, and the SA-subprocess *drivers* (brain/circos — already SA logic). **LB drops** its own `render.py` renderers.
- **LB’s new figure trigger:** where LB now calls `select_renderer`, it instead shells out to `source-analytics figure --analysis <m> --paradigm <p> …` (same `--brain-python` interpreter pattern already used for brain/circos) — *or* simply relies on a `--steps …,figures` analytics run having populated `results/figures/` and only scans.

**Gaps that MUST be closed before dropping `render.py`** (LB is the sole producer today):
1. **Graph-metric nodal heatmap** (`RoiGraphMetricHeatmap`) → port into SA as a `roi_graph`/`vertex_graph` `figures()` output or a `figure`-CLI type. *(vertex_graph/roi_graph currently emit no figures at all.)*
2. **NBS component summary** (`NbsComponentPlot`) → decide whether SA's `vertex_nbs_edges_*` map suffices or add a component-size figure to `_nbs_figures`.
3. **Generic `SummaryHeatmap` / `EffectSizeHeatmap` fallback** → register a general `effect_heatmap` for the remaining analyses (electrode_connectivity, vertex_connectivity/directed/cross_freq tables) in `figure_registry.py`.
4. **electrode_psd/aperiodic** figures are stats-inline, not a cheap figures-only pass — give them a real `figures()` (R `--figures-only`) so the gallery can regenerate them standalone.
5. **MVPA** only matters if `vertex_mvpa` is revived.

**Suggested migration order**
1. Close gaps #3 and #1 in SA (register the missing `figure`-CLI types) — cheapest, highest coverage.
2. Add a `source-analytics figure`-invocation path in LB `builder.py` mirroring the brain/circos subprocess, gated behind a flag; keep `render.py` as fallback.
3. Verify a full gallery built via the SA-only path is figure-complete vs. today's baseline (2200 figs).
4. Delete `render.py` renderers + `REGISTRY`/`select_renderer`; LB retains scanner + brain/circos drivers only.

**Non-goals / keep:** brain-mosaic + circos delegation stays as-is (already SA logic driven by LB). The `--no-figures` R-log cosmetic bug is orthogonal (worth a one-line fix: gate the `message("Saved…")` on `!no_figures`).
